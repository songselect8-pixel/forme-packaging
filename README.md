## 本地预览与生成

推荐双击上级文件夹中的 **启动本地网站.cmd**。脚本会在后台启动本机 Node 服务，并在电脑浏览器打开 `http://127.0.0.1:4173/`；重复打开会复用已有服务，无需安装项目依赖。代码、图片、视频和字体均从本机文件读取。

项目内启动脚本是 `Start-Local.ps1`，服务日志位于 `output/local-server.log`。

只需 Node.js，无项目依赖安装：

```
npm run build
npm test
npm start
```

本地预览：http://127.0.0.1:4173/ 。`dist/` 可直接部署到支持目录索引的静态服务器。`serve.mjs` 支持嵌套目录与视频 Range 请求。

## GitHub 与自动部署

仓库：<https://github.com/songselect8-pixel/forme-packaging>。GitHub Pages 地址：<https://songselect8-pixel.github.io/forme-packaging/>。

推送 `main` 或手动运行 `Deploy packaging website` 工作流后，GitHub Actions 使用 Node.js 24 构建、执行测试并部署 `dist/`。无需安装项目依赖，也无需配置部署密钥。工作流从 GitHub Pages 自动读取网址和仓库子路径，统一生成导航、图片、字体、canonical 与 sitemap。

本地仍直接使用 `npm run build`，并通过上级目录的 `启动本地网站.cmd` 预览；本地路径不带仓库前缀。生产构建可使用 `SITE_ORIGIN` 与 `SITE_BASE_PATH` 环境变量覆盖部署网址和子路径。正式独立域名确定后，再配置 Pages 自定义域名并更新默认 `site.origin`。

从 GitHub 克隆后，在仓库目录运行 `npm start`，或在 Windows PowerShell 中运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Local.ps1`，即可启动本地预览。

GitHub 仅托管已完成的网站及生成所需源码。原始 PNG、检查截图、浏览器日志、服务器日志和其他 `output/` 文件不上传。图片续生成仍处于暂停状态；联系资料和表单发送渠道仍待正式配置。
